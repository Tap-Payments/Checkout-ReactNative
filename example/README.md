# checkout-react-native examples

One example app for the `checkout-react-native` wrapper around the Tap Checkout SDKs, with the same screens as the [Checkout-IOS](https://github.com/Tap-Payments/Checkout-IOS) and [Checkout-Android](https://github.com/Tap-Payments/Checkout-Android) example apps:

- **Main screen:** what the next checkout will do (mode, amount, which key), the main settings, and every callback as a card that expands to its full payload.
- **Settings:** every input of the Tap web demo, grouped like its steps (SDK, User, Card, Order, Transaction), plus **Saved Keys**, **Show configuration JSON** and **Reset to defaults**.

The screens live in [`src`](src) and are built six ways. Both apps are Yarn workspaces of this repository and use the library straight from its source, so changes to the wrapper show up without publishing.

| Command (from the repository root) | Project | Integration |
|---|---|---|
| `yarn ios:pods` | [`ios`](ios) | React Native CLI, `Checkout-IOS` 1.0.7 through CocoaPods |
| `yarn ios:spm` | [`ios-spm`](ios-spm) | React Native CLI, `Checkout-IOS` 1.0.7 through Swift Package Manager |
| `yarn android` | [`android`](android) | React Native CLI, `Checkout-Android` 1.0.9 from JitPack |
| `yarn expo:ios:pods` | [`../example-expo`](../example-expo) | Expo development build, `Checkout-IOS` through CocoaPods |
| `yarn expo:ios:spm` | [`../example-expo`](../example-expo) | Expo development build, `Checkout-IOS` through Swift Package Manager |
| `yarn expo:android` | [`../example-expo`](../example-expo) | Expo development build, `Checkout-Android` from JitPack |

| | React Native CLI app | Expo app |
|---|---|---|

## Requirements

- Node **22.11 or newer** and Yarn 3 (bundled in `.yarn/releases`, no global install needed)
- **iOS:** Xcode 16.3+ (the Checkout-IOS Swift package needs swift-tools 6.1), an iOS simulator, and CocoaPods
- **Android:** JDK 17+, the Android SDK with an emulator, `ANDROID_HOME` set (or `android/local.properties` with `sdk.dir`)

## Running

1. Install the dependencies once, from the repository root:

   ```sh
   yarn
   ```

2. Add your sandbox keys (see [Sandbox keys](#sandbox-keys)).

3. Boot a simulator or emulator, then run the variant you want, from the repository root:

   ```sh
   # React Native CLI
   yarn ios:pods        # iOS, Checkout-IOS from CocoaPods
   yarn ios:spm         # iOS, Checkout-IOS from Swift Package Manager
   yarn android         # Android

   # Expo (development build)
   yarn expo:ios:pods   # iOS, Checkout-IOS from CocoaPods
   yarn expo:ios:spm    # iOS, Checkout-IOS from Swift Package Manager
   yarn expo:android    # Android
   ```

   Each command builds and installs the app, starts Metro if it isn't running, and opens the app. The first build takes a while: it downloads React Native, the Tap SDKs and (for SPM) the Swift packages. JitPack, where Checkout-Android is published, can be slow on a first download.

Notes:

- **Metro.** `yarn start` starts Metro for the React Native CLI app and `yarn expo:start` for the Expo app. Both use port 8081, so run one at a time, or pick another port (`yarn start --port 8088`, `yarn android --port 8088`). On a physical Android device, forward the port first: `adb reverse tcp:8081 tcp:8081`.
- **CocoaPods vs SPM.** `ios` and `ios-spm` are separate Xcode projects; the only difference is `ENV['CHECKOUT_IOS_SPM'] = '1'` at the top of `ios-spm/Podfile`. They share a bundle id, so the last one you run replaces the other on a simulator. The Expo iOS commands run `expo prebuild` first, which runs `pod install` with or without `CHECKOUT_IOS_SPM`, so switching between them needs nothing else.
- **Xcode / Android Studio.** Open `ios/CheckoutReactNativeExample.xcworkspace` (or the one in `ios-spm`) in Xcode, and `android` in Android Studio. For Expo, run `yarn example:expo prebuild` first; it generates `example-expo/ios` and `example-expo/android`.
- **Expo Go** can't run the example: the SDK has native code, so it needs a development build, which is what the Expo commands make.
- **Release builds** embed the JS bundle, so they run without Metro: `yarn example build:android`, `yarn example build:ios` (`build:ios:spm` for SPM). They're signed with the debug keystore, which is fine for testing but not for distribution.

## Sandbox keys

The examples need a Tap **sandbox** public key (`pk_test_...`). Keys belong to your Tap account and are never committed. There are two ways to give them to the app.

**Your own keys file (recommended).** Copy [`keys.local.example.json`](../keys.local.example.json) to `keys.local.json` at the **repository root** and fill it in. It is gitignored, and every entry appears in **Settings › Saved Keys**, where you switch between them:

```sh
cp keys.local.example.json keys.local.json
```

```json
[
  { "name": "My sandbox key", "publicKey": "pk_test_...", "merchantId": "" },
  { "name": "Second merchant", "publicKey": "pk_test_...", "merchantId": "1234567" }
]
```

`merchantId` is optional; leave it empty to use the merchant the key belongs to. Debug builds read the file when Metro bundles the app, so after creating or editing it, reload the app (press `r` in Metro). If **Saved Keys** still doesn't appear, restart Metro with `--reset-cache`.

**Or a default key.** Replace `YOUR_TAP_PUBLIC_KEY` in [`src/Keys.ts`](src/Keys.ts) (and `merchantId` if needed). This file *is* committed, so don't push a key you put there. You can also paste a key into **Settings › SDK Configuration › Public Key** while the app runs.

Tap checks the public key against the app id registered for the merchant. If your key is registered for another app id, change `applicationId` in [`android/app/build.gradle`](android/app/build.gradle) and `PRODUCT_BUNDLE_IDENTIFIER` in the Xcode projects (`checkoutreactnative.example`), or `ios.bundleIdentifier` / `android.package` in [`../example-expo/app.json`](../example-expo/app.json) (`checkoutreactnative.expoexample`).

The badge on the main screen shows which key is in use: **Sandbox key**, **Live key** (a `pk_live_` key, which you shouldn't test with) or **No public key**. Settings are kept in memory, so they go back to the defaults when the app restarts.

**Sandbox test card (3D Secure):** 4508 7500 1574 1019, expiry 01/39, CVV 100.

## Tests

```sh
yarn test
```

runs Jest: the library tests and [`src/__tests__/CheckoutSettings.test.ts`](src/__tests__/CheckoutSettings.test.ts), which makes the same checks as `CheckoutSettingsTests.swift` / `CheckoutSettingsTest.kt` in the native example apps.

The UI tests are ports of the native `ReadmeConfigurationTests`: each one starts the checkout with one README configuration value changed and checks the sheet or the charge against the Tap sandbox. They need a sandbox key and Metro running (`yarn start`):

```sh
# iOS (React Native CLI app; use ios-spm for the SPM project)
TEST_RUNNER_TAP_PUBLIC_KEY=pk_test_... xcodebuild test \
  -workspace example/ios/CheckoutReactNativeExample.xcworkspace \
  -scheme CheckoutReactNativeExample \
  -destination 'platform=iOS Simulator,name=iPhone 17'

# Android (emulator or device connected)
cd example/android && ./gradlew connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.TAP_PUBLIC_KEY=pk_test_...
```

## Code

- [`src/CheckoutSettings.ts`](src/CheckoutSettings.ts): every input of the web demo and `makeConfiguration`, which builds the object passed to `startCheckout` (same mapping as `CheckoutSettings.swift` / `.kt`).
- [`src/screens`](src/screens): the main screen, Settings, the option picker and the JSON viewer. [`src/App.tsx`](src/App.tsx) switches between them (no navigation library).
- [`src/UITestHooks.ts`](src/UITestHooks.ts): lets the UI tests set the key and configuration at launch (debug builds only).
- [`src/Keys.ts`](src/Keys.ts) and [`src/LocalKeys.ts`](src/LocalKeys.ts): the default key and `keys.local.json`.

## Troubleshooting

- **iOS: "UIScene life cycle is required"**: apps built with the iOS 27 SDK must use scenes; `AppDelegate.swift` starts React Native from a `SceneDelegate`. Keep it if you edit the app delegate.
- **iOS: "deployment target is set to 12.0/13.0"**: the Podfile's `post_install` raises every pod below `min_ios_version_supported`; keep that block.
- **iOS: `pod install` fails with `Unicode Normalization not appropriate for ASCII-8BIT`**: run it with a UTF-8 locale, `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install`.
- **Android release: manifest merger `usesCleartextTraffic` conflict**: the Tap Android SDK's manifest sets `usesCleartextTraffic="true"`; the app manifest uses `tools:replace`.
- **Blank screen or a red screen from another project**: the app is talking to a different Metro on 8081. Stop the other one, or run this one on another port as shown above.
- **`SDK location not found`**: set `ANDROID_HOME` or create `android/local.properties` with `sdk.dir=/path/to/Android/sdk`.
